# 拾链 LinkKeeper：简历与面试材料

## 项目一句话

一个本地优先的书签健康体检工具：解析浏览器书签，异步并发检查公开网页，识别失效、重定向、访问受限和重复收藏，并导出整理后的 Netscape 书签文件。

## 中文简历表述

- 独立设计并实现 LinkKeeper 书签健康平台，支持浏览器书签解析、异步并发探测、URL 规范化去重及整理后书签导出。
- 设计基于任务 ID 和进度轮询的异步扫描架构，将最多 300 条链接分发到并发线程池，页面可实时展示扫描进度和结果。
- 实现 HTTP 状态语义分类、HEAD→GET 回退、重定向追踪、页面标题提取和跟踪参数清理，区分真正失效与登录受限页面。
- 构建 URL 安全校验层，阻止环回、私网、保留地址、账号密码 URL 和非标准端口，并校验重定向目标，降低 SSRF 风险。
- 使用原生 HTML/CSS/JavaScript 完成中文响应式界面，通过 Python 标准库提供解析、扫描、汇总和导出 API。

## 面试讲法

### 为什么采用异步任务

一次扫描可能有数百个慢站点。同步等待会让浏览器长期占用连接，也无法展示真实进度。任务 ID 让扫描与页面请求解耦，轮询接口返回已完成数量和阶段性结果。

### 失效与受限为什么要分开

404/410 通常说明资源消失，但 401/403/429 可能只是登录、反爬或频率限制。把它们都标为失效会给用户错误清理建议。

### SSRF 防护做了什么

- 只允许 HTTP/HTTPS 和 80/443 端口；
- 拒绝 userinfo、localhost、私网、环回、链路本地和保留地址；
- 在每次重定向前再次校验目标；
- 保持短超时和小响应读取。

更严格的生产环境还应通过受控出口代理固定 DNS 结果，防止 DNS rebinding。

### 项目边界

扫描任务保存在内存，服务重启会丢失；这是为了保持本地工具零依赖。生产化可增加 SQLite 历史、账户权限、分布式限流和站点级失败缓存。
